## 实现结果

| 阶段 | 结果 |
| --- | --- |
| UI | 服务读取使用 aiOf；运行时状态独立监听；数据域订阅收敛；金额、头像、账单分组、统计、方案和聊天派生结果缓存。状态更新不重建历史消息，AI 聊天写入不重建保留的财务标签页。 |
| 写入 | Frozen / Cow JSON 保留未变子树；按引用通知；无变化财务列表复用。用户消息与任务启动合并，计数随检查点提交；两轮、三个只读工具的回复共提交三次。 |
| Worker | load / commit / query / restore 顺序执行于共享常驻 worker；30 秒超时；异常类型保留，退出后拒绝挂起请求并在下次请求重建。元数据只传变化值和顺序 ID。 |
| 存储 | 原生 schema 2、WAL / FULL；逐请求关闭连接并抑制关闭时强制 checkpoint。恢复副本空闲 3 秒或退到后台同步；失败不回滚已提交主库；迁移、恢复、损坏修复等待副本完成。 |
| 留存 | 新消息只存当前协议回放；最近 15 个用户轮次外压缩已完成消息，错误与取消检查点保留。首次延后压缩存量；回执 30 天 / 1,000 条，已结束任务 200 条，已处理操作和批次各 500 条。 |
| 渲染 | 标签只位移；首页整页一次淡入，分区错峰位移；其他标签延后 1 秒逐帧预构建；窄屏去掉重复背景；消息和处理记录使用 SelectionArea，缓存约 1.5 屏。局部玻璃模糊保留。 |

订阅核对时另保留 `dismissedSuggestions` 的 preferences 通知、`savedRecipes` 与 `voiceDrafts` 的 tasks 通知，并单独监听语音排队状态，确保收敛后这些操作仍立即更新。

## 自动化基准

Windows 桌面 Flutter 测试运行器、JIT；所有命令先加载 `scripts/environment.ps1`，使用项目 `.pub-cache`。以下不是 ARM64 真机帧数据。

| 基准 | 结果 |
| --- | --- |
| 2,000 条聊天，每条三个 8KB 工具结果；无磁盘工作的 metadata sink；七次追加取中位值 | 修改前 5,634µs；写时复制阶段 297µs；最终 324µs，较基线约减少 94%。 |
| 10,000 笔账单；连续五次持久化追加取中位值 | 写时复制阶段 SQLite 29,650µs；worker 阶段 25,583µs；最终 SQLite 21,907µs，同轮 JSON 287,790µs。每次修改两行：账单及账本 revision。 |

最初 SQLite 基准已有 `lastChangedRows == 1` 断言失败，实际为 2；修正后记录后续阶段结果，未把旧审计的不同轮次数据作为本次原始基线。

已核对运行中的 SQLite 与缓存 Android ARM64 库均为 3.53.4，支持 `VACUUM INTO`。运行时同时检查最低版本；未通过打包生成新 APK 来核对。

## 交付限制与数据行为

**原生数据库版本为 2，不支持降级至旧版应用，OTA 回退也须遵守这一限制。** 主库提交立即持久化，恢复副本为异步快照，可能落后。主库损坏时保留主库、WAL、SHM 后从已校验副本恢复，并提示副本之后的修改可能丢失；恢复点和导出备份仍可用。浏览器后端保持原有实现。

当前仅有 Windows、Chrome、Edge，没有连接 Android 手机。S1–S6 的真机基线及复测、120Hz 的 p90 / p99 目标、聊天长按和跨段落选择复制尚未验证，不能据自动化基准宣布真机性能达标。
