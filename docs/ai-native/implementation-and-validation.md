先冻结接口与语义，再逐段替换。每阶段都保持应用可用；领域抽取、SQL 迁移、提示词升级和 UI 重画不能混成一次不可验证的大改。

  S1 --> S2[S2 状态与性能隔离]
  S1 --> S3[S3 能力目录与应用知识]

以上是依赖关系，**不是要求同时启动多个 agent**。S2 / S3 接口可以协同设计；S5 的语言设计已在协议中冻结，但数据迁移应在现有一致性测试稳定后执行。优先完成“查询 → 补账户 → 准备一份方案 → 一次确认 → 重启可查回执”的纵向场景。

不预先承诺 0.4.0 已完成。实施时依据最新应用版本、阶段交付范围和 Agent.md 选择新版本号。

## 3. 阶段与完成门槛

### S0：建立不依赖 AI 的基线与语义合同

范围：

- 固定合成测试账本：空账本、1千 / 1万 / 10万笔、不同账户 / 转账 / 退款 / 归档 / 未关联历史数据。
- 核对现有测试与配置；记录各平台能力，而不是假设 Android、Web 等价。
- 把 R01–R04 改成期望正确行为的回归测试，缺陷在后续对应阶段修复。
- 固定当前余额、收支、退款、导入保余额、日期和隐私语义；将对外 QueryResult / ErrorEnvelope 定义为纯 Dart 类型。
- 建立非 AI 入口清单与测试，明确识别服务和语音语义解析仍可能有额外依赖。

完成：可复现实测报告、合成数据生成方式、未通过项清单。不能为使测试通过降低原有账本校验。

### S1：共享业务内核与提交策略

主要文件落点：domain/ledger_operations.dart、domain/models.dart、data/wallet_store.dart，services 中 agent_actions、voice_bookkeeping、payment_notifications、wechat_bill_import；新增 application/ledger_commands.dart / ledger_queries.dart 等按职责命名。

范围：

- 接通现有 LedgerOperations；新增、编辑、幂等新增、删除、账户校正、转账与分类验证共同实现。
- 来源适配器保留通知退款、导入保余额、语音候选和方案规则，调用共同内核。
- 引入明确的业务命令上下文；在提交队列内检查锁、账本世代、相关版本和执行策略。
- 提交与维护操作区分，保留恢复与解锁入口；避免简单在所有 change 前加 locked guard。
- 领域类型不引用 AgentActions、Flutter、数据库或模型协议。
- 同业务命令同时写入来源状态与回执；不为每笔批量记录分配一次磁盘提交。

完成门槛：

- R01、R02、R05 修复；五入口对相同标准化交易给出相同结果。
- 排队后锁定、同 ID 不同内容、重复点击、过期记录、归档账户、同账户转账、非法分类均被测试约束。
- 入账失败、主库 / 恢复副本失败、退款累计、导入保余额、条件撤销、旧备份恢复回归不退步。
- 非 AI 路径模型请求数为 0。

### S2：隔离数据成本、UI 订阅与运行资源

主要落点：WalletMetadata / WalletStore、storage_base / storage_sqlite、AppScope、页面 ViewModel、AiService 的状态发布；保留 native / Web 适配器。

范围：

- 已初始化后的聊天 / 配置 / 记忆提交走 metadata 通道，仅传涉及域，不能用标记绕过校验。
- 为 ledger、tasks、conversations、preferences、memory、sources 定义变更通知。预算属于 ledger 业务版本，主题属于 preferences；按含义分类，不按旧 JSON 所在桶分类。
- 账单、资产与统计只订阅相关变化；AI liveUpdates 和日志独立。
- 已提交读视图不可变，缓存按域或依赖版本失效；财务错误保存不使新数据混入缓存。
- 模型请求与账本提交队列分离；等待网络不持锁。取消按 requestId，而非误取消另一个页面的请求。
- 有界队列保留忙时语音草稿，明确进度与取消，不阻塞手动输入。

完成门槛：

- R03、R04 修复。1 万笔已初始化账本新增对话：传输 / 扫描 / 修改财务记录数均为 0。
- 聊天 token、日志、AI busy 触发财务页面重建为 0，真实财务修改仍正确刷新。
- metadata 首次初始化、连续混合写、失败回滚、重启恢复、失效实例拒写均通过。
- 同时打开聊天并手动录入，保存不等待模型完成。
- 测量剩余元数据复制与启动全量加载成本，不声称此阶段实现所有常数成本操作。

### S3：能力目录、AppSpec 和上下文

主要落点：新增 application/capabilities、agent/context、agent/prompts；ai_service 和 openai_transport 保留为兼容 / 协议适配器。

范围：

- 将工具定义和路由合并到静态注册表，旧工具名映射到新能力。
- 建立 AppSpec，注册表生成能力说明；核心机制固定，领域说明按需获取。
- QueryRepository 先适配当前数据，所有查询带单位、范围、版本、完整性、来源引用。
- 最小投影与上下文预算，不把全量账本或全部用户画像每轮注入。
- 记忆 / 目标 / 偏好建立代码级策略，移除任意模型直接改 JSON 的捷径。
- PromptAssembler 先支持 legacy 模式，再对已实现能力开放目标模板。

完成门槛：

- 新增读能力不需要修改 AiService switch，生成 schema 与执行器保持契约一致。
- 未注册工具、未知字段、跨任务对象、超限参数受到运行时拒绝。
- 元 / 分、时间边界、全量汇总 / 分页、归档和退款口径一致。
- 模板变量全部替换；未实现的工具不能进入可调用清单。
- 先执行机制理解评测 E01–E05、E14–E17、E20–E25；硬权限同时有确定性测试。

### S4：独立任务、补充交互、方案与回执

主要落点：新增 agent/task_runtime、application/tasks、application/interactions；迁移 AgentActions；复用并改造 AgentBatchCard / ReviewPage 与 ai_pages。

范围：

- 独立 taskId；一个任务可跨会话和页面，允许没有聊天消息。
- 实现协议中的 NodeOutcome、TaskState、InteractionRequest、ReviewPlan、AuthorizationGrant。
- 迁移现有 batch / receipt，保留原始用户消息和来源引用。
- 缺失字段以结构化补充卡呈现；自然语言调整更新原任务。图形卡只渲染合同，不直接决定授权。
- confirmation 核验版本、选中集合、依赖闭包、相关数据版本与账本世代。
- 操作、状态与回执原子保存；提交结果由宿主呈现，不等待模型。
- 崩溃恢复和重试先查实际回执；“停止生成”与“放弃任务”区分。

完成门槛：

- “从导入页补账户 → 聊天补信息 → 回审阅页 → 一次确认”完整走通，不复制任务。
- 一批多调用仍是一张方案卡；明确项可执行，暂定项默认不选。
- 旧卡点击、重复响应、切换对话、更新方案、相关记录变化、恢复账本后旧授权全部覆盖。
- 进程在写入前、事务中、提交后 UI 更新前被中断，均不会重记。
- 保存 / 撤销失败保留草稿与选择，回执准确。
- 通过 E06–E13、E26；320px / 大字体 / 键盘 / 返回键 / 无卡片回退通过。

### S5：记录级查询、关联迁移与 AI 查询编程

先完成查询能力的语义和存储迁移，再启用 QueryRecipe。禁止把任意 SQL / JS 执行器作为第一版。

范围：

- 引入 command ChangeSet、记录级更新和版本，减去全量差异扫描。
- 交易查询与聚合使用明确的索引 / 字段，支持稳定游标；schema 不要求照搬某个 ORM。
- 在一次协调迁移中落地 categoryId、source refs、退款关联、日期精度；歧义数据不猜测。
- 保留单一权威数据与恢复副本；派生索引可重建，旧备份仍可导入。
- 按协议实现 QueryRecipe parser、type checker、scope checker、cost budget、executor；语言版本固定，新增算子有独立测试。
- 程序默认临时，保存为常用分析由用户触发；权限每次执行重验。
- 数据量超预算明确失败或完整使用受支持聚合，不静默采样。

完成门槛：

- 单笔提交仅传受影响记录，更新范围可观测；分页和整范围汇总对照旧结果。
- 恶意字段、跨域访问、循环 / 递归、超时、不允许关系、溢出、零分母、过期快照、取消均被测试。
- 同一问题可由模型组合出未预设命名的查询；E18、E19 通过，结果金额与合成账本精确相符。
- 1千 / 1万 / 10万笔的启动、保存、查询、跨 isolate 载荷、文件大小、峰值内存有报告。
- 所有迁移故障测试通过；尚未实现的算子与能力清楚标记。

## 4. 数据迁移与兼容检查表

| 变化 | 迁移要求 | 必须保留 |
| --- | --- | --- |
| WalletMetadata / 状态拆分 | 仅改变组织方式时不升级业务 schema | 原数据值、失败回滚、原生 / Web 语义 |
| taskId 独立 | 旧 batch ID 通过映射关联新任务；迁移重跑不重复创建 | 用户消息、选中范围、提案版本、原回执 |
| categoryId | 按类型与旧名称映射；歧义保留待处理 | 历史显示名称，不误合并同名不同类型 |
| 来源与退款 | 能证明的关联才迁移，未知为 unknown / null | 原备注、原事件、原交易 ID |
| 日期 | 旧无时区字段按旧本地语义；记录迁移假设 | 用户过去看到的业务日期、精度信息 |
| 记录级 SQL | 迁移事务内验证条数、金额、关联、校验和 | 旧 JSON、恢复副本、未来版本拒绝降级 |
| 备份与附件 | 格式声明必需字段与版本；附件哈希校验 | 用户附件与来源引用，损坏时明确错误 |
| 记忆规则 | 标注来源与旧记录兼容，不强推全部画像 | 用户已知偏好、明确删除语义 |
| 清理与保留 | 先检查任务 / 回执 / 来源引用；记录策略 | 账单不因 AI 上下文或内存清理而删除 |

无需引入完整事件溯源。保留必要执行记录和撤销依据即可。备份恢复是显式维护命令，和普通入账审批不同；发生恢复后 ledgerEpoch 变化使旧授权、快照和游标失效。

## 5. 性能测量合同

自动化关注确定性计数：

- 每次命令的受影响记录数、跨 isolate 载荷量、比较 / 查询行数、修改行数、落盘次数。
- 财务页面、聊天消息、输入框重建次数；长列表实际挂载行数。
- 节点调用数、模型轮次、修复次数、上下文字节数、取消后遗留工作数。
- 缓存命中和失效范围，提交失败后的结果一致性。

计时基准记录构建模式、机型、系统、刷新率、数据构成、冷热启动、重复次数与分位数。规模为 1千 / 1万 / 10万笔，另加长聊天 / 大来源文件场景。10万笔是压力场景，不据此让普通页面全量预加载。

真机体验包括：连续中文输入、键盘开关、滚动、搜索连输、保存、切换统计周期，同时 AI 流式输出或准备批次。60Hz / 120Hz 分别按刷新预算分析 UI 与 raster，不只报告平均耗时。

建议先选中档 Android 真机作为基准，建立 p50 / p95、掉帧与内存峰值，再制定该机型发布阈值。测试环境中毫秒值波动较大，单测不使用任意极小耗时断言。
