# Agent 任务级审阅与执行

## 用户流程

一次用户任务对应一份方案，不以模型工具调用次数拆分确认。聊天只显示汇总卡片：准备状态、范围、操作分组、待核对数量、实际余额影响和统一确认按钮。明细进入独立审阅页，支持全选明确项、逐项排除、直接修改、处理冲突。暂定项默认不选；涉及金额、账户、日期和预算的变化显式展示。

Agent 不先要求口头批准再逐笔确认。确认始终针对页面上已审阅的方案版本及选中项。生成期间不执行；中断后可继续准备，也可明确选择仅执行已准备部分。历史方案与未关联消息的提案都能审阅。

## 痛点对应

| 用户遇到的情况 | 设计与实现 |
| --- | --- |
| 数十张卡片占满对话、逐笔确认 | 单张方案卡片只显示最多四组摘要，统一按钮确认当前选中范围；明细列表按需进入、逐行加载 |
| 看不出实际修改了什么 | 默认摘要显示分类、日期、金额、账户、方向、名称与备注差异；完整明细展示余额影响 |
| 少量暂定项拖累整批处理 | needsReview 默认不选中，提供“待核对”筛选、直接编辑和明确项选择 |
| 用户修正后出现两份方案 | revise_changes 修改原任务，同目标字段合并；旧审阅失效并提示刷新 |
| 准备停止，用户不知道是否完整 | 展示已准备数量与中断状态；未完成的方案须继续准备或明确选择执行已准备部分；准备工具失败不能显示为完整方案 |
| 提案期间账本被修改 | 冲突项单独标记；按最新账本预览并重审，提交前再次校验；其他明确项仍可选择 |
| 新增账户和账单需要先后操作 | 任务内稳定引用，系统按账户再账单执行；默认选择排除尚待核对的依赖，勾选明确账单会同时选中所需账户 |
| 写入或撤销一半失败 | 统一验证、一次提交，失败全部回滚；错误保留在当前审阅页，不产生成功回执 |
| 确认后聊天继续被回执刷屏 | 每批只保存一条用户决定和一条汇总结果；单项排除保留提案状态，不追加逐笔聊天回执 |
| 返回、重启后丢失处理上下文 | 返回时保留选择；启动恢复未完成方案，回复尚未保存时重建续接入口并绑定原始用户消息 |

## 数据与授权

- `agentActions` 保留单项提案及 before/desired/after 快照；新增 batchId、needsReview、reviewNote。
- `agentActionBatches` 在现有 extras 中保存任务来源、会话、方案版本、准备状态、回执和执行范围；不改变备份 schema 或 SQLite user_version。
- 一次回复 ID 是任务 ID，重试沿用，其他任务与会话不能混入。历史单项按原始回复归组，缺少来源的提案独立归组。
- 自然语言修正已有方案时保留任务 ID，更新来源回复；恢复时使用原始用户消息 ID，不能错误续接后来的提问。
- 修改、替换、排除、继续生成都会使审阅版本失效；提交检查方案版本、完整提案快照、选中范围及账本 before 状态。
- 同任务相同目标只保留一项有效提案；新增账户可通过任务内引用关联后续账单。模型只能准备提案，不能执行、拒绝或撤销。

## 执行与恢复

统一检查所有选中项，再在一次 WalletStore.change 内写入账本、状态和一份回执。失败全部回滚，保留选择与错误位置。独立冲突项可排除或基于最新账本重新审阅；缺少依赖时不执行。每次执行有独立回执及范围，重试不重复记账；撤销整个回执时先检查全部执行后状态，再一起恢复。

大任务可用一次 propose_changes 工具提交多项（每次最多 200 项，整个待确认队列最多 2000 项）。准备状态显示业务数量，不用工具次数冒充完成度。get_pending_actions 按当前会话分页查询，返回数量、方案版本和准备状态。

审阅和执行逻辑分别位于 `AgentBatchCard`／`AgentBatchReviewPage` 和 `AgentActions`。原有单项接口保留兼容；新的模型提案自动进入任务方案。方案及回执与账本一起保存，不引入新的服务或依赖。

## 验证

覆盖批量提交与撤销的原子性、保存失败、重复提交、审阅后方案变化、账本冲突、暂定项、不同任务与会话隔离、新增账户依赖、历史提案、断流后续接、320px 大字体和长列表。保留原有迁移、恢复、SQLite、支付通知及语音记账回归。交付版本 0.2.0，构建号递增到 4。

最终验证：205 项通过，1 项私人样本测试跳过；静态检查无问题，release 安装包构建及签名验证通过。完整交付信息见 [0.2.0 发布说明](https://github.com/bownyu/fin-dash/releases/latest)。尚未替代实际模型网关和实体手机验收。
