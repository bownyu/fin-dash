# FinDash 0.5.6

日期：2026 年 10 月 4 日。Android 构建号：15。从 0.5.5 可直接覆盖升级。

## 语音多笔金额识别

旧语音入口单独调用模型提取 JSON，没有调用通用 Agent 的记账工具。它的提示词要求“一次只处理一笔”，返回格式、服务和确认页也只接受单笔；多个金额不能判定时要求返回空金额。对于“午饭18块钱、咖啡3块钱，都是中国银行”，这组限制与用户要记录两笔的目标冲突。

- 提示词改为按用途拆分全部交易，每个明确金额分别换算为整数分；共同付款账户与日期作用于对应交易。说明原价、优惠、实付、合计、口头纠正的区别，避免多记合计或误用原价。
- 新返回格式为 `entries` 列表，兼容原有单笔对象和直接 JSON 数组。整数值数字或数字字符串归一化为整数分，不猜测缺失金额或货币单位。
- App 列出每笔的用途、金额和账户，可逐笔切换编辑。说一句修改时携带全部草稿及当前选择的账单，保留未修改记录；模型漏掉原有账单时报错并保留草稿。
- 真正缺失的字段仅标记对应账单；全部有效后由用户一次确认保存，沿用同一账本事务、幂等 ID 和逐笔回执。保存失败整批回滚，重复确认不重复入账，支持整批撤销。
- 小部件可显示并保存两笔收支，共同换账户；多于两笔或包含转账的多笔草稿会保留在任务页，必须到 App 逐笔核对。任务页恢复已解析的草稿，无需重新请求 AI。

## 数据兼容

不改变 SQLite `user_version`、备份 schema、账户余额计算或原生通知收件箱。多笔语音草稿继续使用现有扩展元数据，单笔草稿与小部件协议保持兼容。持久化完成后才更新内存账本和 UI。
