# FinDash 0.6.0

日期：2026 年 10 月 4 日。Android 构建号：19。从 0.5.9 可直接覆盖升级。

本版包含 AI 顾问改造，并合并了此前单独开发、未发布的首页层次设计（原稿编号 0.5.7，已被导航修复占用）。两者此前都没有构建安装包，因此合为一个版本发布。

## 顾问提示词

`PromptAssembler` 的身份从“账本管理助手”改为长期财务伙伴，`promptVersion` 升至 2。新增三部分规则：

- 关系与情感：先回应情绪再谈数字；谈行为和感受，不推断人格、不责备；具体肯定进步；遇到严重经济或心理困扰时先关心安全。
- 陪伴成长：一次聚焦一个本周可做到的行动，并与目标相连；用户同意时准备约定，到回访日自然跟进；有账单依据的行为规律可作为观察提交审阅，个人事实只记录用户亲口所说。
- 复盘与分析：用户要总结或分析时，先一两句说清整体情况和与平时的差别，只挑一两个值得注意的点并说明对目标或预算意味着什么，结尾给一个小行动或问题。默认用自然段，不用小标题、编号列表或“三条变化”式罗列，只引用支撑观点的两三个数字；一次性支出与日常习惯分开看，异常检测结果不原样转述。此前的“最多 3 条观察”规则会让模型输出清单，已移除。
- 篇幅：查询结果、回执和方案说明仍保持简短；聊感受、目标或计划时允许 2–5 句自然对话。

AppSpec、授权规则、查询程序限制原样保留。

五种交流风格改为固定的行为描述，按枚举值放入规则区。此前 `tone` 只出现在声明为“非指令”的资料 JSON 中，模型可以忽略。

## 用户简报

每轮请求在资料区附带 `user` 简报：称呼、画像、标签、交流偏好、关注领域、最近的观察、进行中或暂停的目标（金额 / 期限 / 原因）、进行中的约定（到期标记 `due`）、已完成约定数、本月原始支出 / 收入 / 预算使用率、上一次非当天的聊天（日期、间隔天数、话题），以及是否初次交流。本月数据在请求时实时计算。

此前人设页的“额外指引”和“关注领域”没有传给模型，偏好、画像和目标只能通过工具读取。现在额外指引以 `style.note` 传入，只影响表达方式。每个字段都有条数和长度上限，记忆召回改为最多 8 条、1,500 字，整体仍受 16 KB 上限约束。

## 约定与目标

新增 `set_commitment`，与记忆、偏好、目标共用确认卡片流程：模型只能准备，用户在本地确认后保存，可以撤销。约定包含内容、回访日期、状态（进行中 / 做到了 / 没做到 / 已放弃）和结果备注；最多保留 50 条，超出时先移除最早的已结束约定。确认卡片的摘要改为按工具生成可读文本。

`update_plan` 新增 `target_cents`、`deadline`、`motivation`，新建目标记录 `createdAt`。目标编辑页可填写“为什么想实现它”，目标卡片显示期限和原因。

准备类工具的描述改为保留原有说明并追加“须本地确认”，此前统一替换成同一句话，模型无法区分工具用途。

## 界面

- 聊天页空状态按本地数据生成开场白：到期约定、上次聊天的话题或进行中的目标，不调用模型。
- 快捷指令改为“聊聊目标 / 这周花得怎样 / 有点焦虑 / 定个小计划”，有到期约定时增加“约定回顾”。输入框提示改为“聊聊收支和目标，或说说想记的账…”。
- 顾问记忆页新增“我们的约定”，可删除；“核心洞察”改为“洞察与观察”。人设页的风格选项与提示词共用同一份定义。
- 回复中紧贴中文标点的粗体（如 `**本周：支出 759.84 元。**上周…`）按 CommonMark 规则不会生效，星号会原样显示。聊天与思考摘要的 Markdown 增加一条不受标点限制的粗体解析，代码片段内的星号保持原样。

## 首页层次

0.5.6 的首页各区块大多是同样描边、同样底色的卡片，主次主要靠字号区分。本版用表面层级拉开主次，并保留玻璃材质：

- **资产主卡**：保留半透明渐变、高光描边和轻投影，是首页唯一带投影的卡片。“净资产 / 总资产 / 总负债”选择器作为卡头；原先卡头的标签与“↕”切换和选择器重复，已去掉。金额隐藏按钮移到金额右侧。资产卡因此少一行，首屏能露出更多内容。
- **月度摘要**：本月收入与支出合并到一块面板，中间用细线分隔。宽屏时仍在资产卡右侧上下排列。
- **操作区**：“记一笔 / 转账”改为无边框的浅色块按钮，文字为正文色；“AI 顾问 / 语音记账”保留描边表面和强调色图标。两行按钮的位置与间距不变，核心入口仍在首屏完整可点。
- **账单行**：金额列原先与标题平分剩余宽度，导致金额停在行中间、长标题被截到一半宽度。现在金额列按内容宽度靠右（最宽 140 逻辑像素，超长时缩小），并使用等宽数字，标题占用其余宽度。账单页、账户流水等所有账单列表同步生效。

## 首次动画

0.5.1 让主标签的首次切换也有动画，但动画时钟在切换当帧就开始计时。首次进入的页面要在这一帧完成构建，如果构建耗时接近动画时长，下一帧画面已接近终点，看起来仍像直接换页。

- 新增 `SettledStart`：动画进度在首帧（构建帧）保持为 0，从下一帧开始计时。
- 主标签切换、首页首次淡入，以及所有子页面推入（`openPage`、聊天会话切换、支付记录核对）都使用该方式。返回动画不受影响。
- 只多等一帧（约 16 ms）；系统开启“移除动画”时仍直接跳到结果。

## 底部导航

首页设计原稿把选中状态改为一块在各标签间滑动的高亮，图标与文字颜色渐变。这与 0.5.7 的修复冲突：滑动和渐变期间，选中背景与颜色会落后于当前标签。合并时保留 0.5.7 的实现：选中背景、图标和文字在切换当帧更新，点击无水波，悬停与焦点使用轻微中性色。导航按钮行的代码整理（`_navRow`）一并保留。

## 数据兼容

约定保存在 `agent.commitments`，旧账本缺少该字段时按空列表处理；目标新字段均为可选。不修改账本结构、SQLite `user_version` 或备份 schema。`markdown` 由间接依赖改为直接声明，版本仍为 7.3.1。

- 粗体解析用临时测试核对：中文标点旁的粗体不再显示星号，代码片段内的星号保留；临时测试已删除。
