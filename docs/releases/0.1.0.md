# FinDash 0.1.0 Release Notes

发布日期：2026-10-02 · Android 构建号：3

本次更新重点改善消费确认和输入体验，并将原生账本升级为 SQLite 增量存储，让日常记账不再反复编码、重写整个 JSON 账本。

## 消费确认更直接

- 在提醒弹窗内直接确认单笔消费，无需先进入完整账单页面。
- 新增全选、取消全选和批量确认，账户选择与确认操作固定在底部。
- 更突出地显示微信／支付宝来源、金额和日期，通知原文及编辑入口按需展开。
- 增加选中反馈和展开动画；退款、疑似重复和信息不全的记录仍需单独核对。

## 输入与浏览更流畅

- 缩小“记一笔”和语音记账页面响应键盘高度变化的范围，减少整页重建。
- 连续输入时避免不必要的页面更新，保留中文输入中的组合文本。
- 账单列表、账户流水改为逐行加载，同一天有大量消费也不再一次构建全部记录。
- 搜索合并连续输入，并复用账户索引和搜索文本，减少重复计算。

## 支付通知监听更容易恢复

- 打开 App 时，对已开启、已授权但未连接的监听自动请求恢复。
- “支付通知识别”页面新增“重新连接监听”，显示实际连接结果。
- 系统仍未连接时提供设置入口。厂商省电限制仍可能影响监听，重连不能补回断开期间未采集的通知。

## SQLite 增量账本

- 原生端按记录保存账单、账户、聊天和通知；普通修改只更新变化的数据库行。
- 差异计算、校验、编码和数据库写入在后台执行。
- 普通交易仅校验变化的交易；导入、恢复及账户结构变化仍进行完整校验。
- 主账本和恢复副本通过同一事务提交；写入失败时保留原来的内存状态。
- 增加多实例版本检查，避免旧实例覆盖另一实例已保存的数据。

## 升级说明

- 首次启动会校验旧 JSON 账本并自动迁移；迁移成功后保留原文件。
- 若旧主文件损坏，会尝试校验并读取旧恢复副本；两者均不可用时提示恢复，不会静默创建空账本。
- 原有 JSON 导入、导出继续可用。建议升级前导出一份备份。
- 旧版 App 不识别 SQLite。迁移后的新增记录不会写回旧 JSON，因此不建议直接降级；降级前应先导出最新版账本。
- 浏览器端继续使用原有存储后端，本次 SQLite 性能改进适用于原生端。

## 版本规则

以用户指定的 `0.0.1` 为版本管理起点。本次存储升级按“大改动”发布为 `0.1.0`。后续普通改动递增末位，大改动递增中间位，最大改动递增首位。

开发环境：恢复 Windows 项目内 Pub 缓存路径，修复跨盘依赖导致的 Android Studio Gradle Sync 错误。开发时使用 `Open-Android-Studio.cmd` 或 `scripts/dev.ps1` 入口。
