# FinDash 0.5.3

日期：2026 年 10 月 4 日。Android 构建号：12。从 0.5.2 可直接覆盖升级。

## 首页核心入口

此前四个快捷操作都排在资产与月度收支之后，可用宽度不足或字体放大时变成两行。“AI 顾问”和“语音记账”位于第二行，初始画面可能被底部悬浮导航遮挡，需要先滚动才能点击。

本版明确初始首页的优先级：

- “AI 顾问”和“语音记账”组成独立双入口。初始位置利用首屏剩余空间，靠近玻璃导航上方，并留出点击间距。
- 首屏布局使用实际可用高度和导航安全区；两入口仍在同一个滚动视图中，用户滚动后会跟随内容移动。
- 较矮屏幕或较大字号采用紧凑资产摘要；空间不足时将月度收支、支出详情、资产选项与次要操作放到入口之后。手动记账仍可直接使用导航中央的“+”。
- 大字号入口使用上下排列的图标与文字；两倍字号时长名称分为完整词组，保留阅读与点击空间。
- 保留现有米白 / 暖灰配色、半透明卡片和玻璃导航。导航首次切换动画、统计选择、账单搜索和滚动状态继续保留。
- 待确认支付在紧凑布局中使用简化摘要，极窄屏大字号下可随内容滚动访问，不挤掉核心入口。
- 月度收支标题在空间不足时正常换行，避免大字号下横向溢出。

## 数据兼容

不修改账本数据、存储结构、SQLite `user_version` 或备份 schema。

## 验证

- 静态检查无问题；Flutter 全量测试 321 项通过，1 项因缺少本地私人样本跳过。
- 新增 56 项首屏回归：48 项尺寸 / 字号 / 外观组合、2 项较大系统安全区、2 项待确认支付、2 项空账本、实际打开 AI / 语音入口与随内容滚动、尺寸变化与标签返回。
- 尺寸组合覆盖 320×568、360×640、390×844、412×892、430×932、600×960 逻辑像素；每种均检查 1、1.3、1.6、2 倍字号与深浅外观。检查按钮完整位于玻璃导航上方、中心及四角可点击、点击区至少 48 逻辑像素，随后滚动检查布局。
- 使用本机字体完成 Flutter 渲染检查，包含与反馈画面相近的 412×892 / 1.3 倍字号，以及 320×568 / 2 倍字号；首屏和滚动后均无布局溢出。预览使用示例账本，设备字体可能略有不同。
- 保留原有导航、金额隐藏、支付核对、账本存储、迁移及恢复测试。

- ARM64 Flutter release 构建成功，应用 ID 为 `com.findash.fin_dash`，版本为 `0.5.3+12`；签名验证通过，签名证书与 0.5.2 一致，可覆盖升级。
- Android 插件继续使用项目内 `.pub-cache`，没有新增依赖。

真机触感与帧率仍需在目标设备体验。
