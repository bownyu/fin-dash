# FinDash 0.5.0

日期：2026 年 10 月 3 日。Android 构建号：9。从 0.4.1 可直接覆盖升级。

## 语音记账

识别出错后，原来的修正方式成本较高：

- 录音时界面只有一条进度条，录完才知道有没有录到声音。
- 识别模型（约 228 MiB）在点结束后才开始加载，加载和解码都排在结束之后。
- 错一个词只能整句重说，或改文字后重新请求 AI。
- 核对页是 6 个输入框，看不出哪些字段是用户说的、哪些是 AI 猜的，只能逐项检查。
- 提示词没有说明文字来自语音识别；SenseVoice 只支持 greedy 解码，不能用热词，账户名和商家名常被识别成同音字。

本版改动：

- **底部面板**：语音记账改为首页上的底部面板，点首页入口直接开始录音。面板关闭了下拉手势，因为下拉会绕过未保存提醒；可以用关闭按钮、点遮罩或返回键关闭，都会先询问是否保留未保存内容。
- **录音反馈**：录音按钮展开为“结束说话”，显示时长和音量条。开始 3 秒内一直没有达到说话音量时，提示“还没有听到声音，请靠近麦克风说话”，不会结束录音。原生端每 100 ms 计算一次音量（-60 至 -20 dBFS 映射到 0 至 1）。
- **更短的等待**：识别模型与 VAD 在录音开始时由低优先级线程加载，结束录音后只需等待解码。录音提前失败时，会等加载完成再释放模型，保证不会同时持有两份模型。
- **AI 纠错**：
  - 提示词说明文字来自本地语音识别，可能有同音字、错别字和不统一的数字写法；账户可按简称或读音匹配，商家写成常见名称。
  - 附上最多 5 笔标题相近的已确认账单。用户以前改正过的账单本身就是纠错记录，因此不新增存储。
  - 模型通过 `assumed` 标出推测的字段，例如默认账户、按历史填写的账户、拿不准时使用的“其他”分类。
- **账单卡片**：
  - 核对页改为账单卡片：金额、用途可以直接改，账户、分类、日期点开即选，使用 App 统一的选择面板。
  - 缺失的字段标红，主按钮变成“选择付款账户”“填写金额”等，点击后直接打开对应的选择面板或输入框。
  - 推测的字段标“推测”；用户改过之后，标记随即消失。
- **说一句修改**：核对时点麦克风说一句修改（如“改成招商银行”），当前草稿和这句话会一起交给模型，模型只改动提到的字段，原文记为“原话；补充：新话”，改动的字段短暂高亮。桌面小部件的“补充”改用同一逻辑（`VoiceBookkeeping.supplement`），并沿用原草稿的 ID，不再在“任务与回执”中留下多余的草稿。
- **修复**：同一次打开面板时，保存后点“再记一笔”会沿用上一笔的 ID，确认时报“这笔记录已经保存”。现在保存成功后会为下一笔分配新的 ID。

## 首页动效

- 首次进入时各区块依次淡入、上移，约 0.6 秒；切换标签页回来不会重播。
- 净资产、总资产、总负债的选中高亮改为滑动；标题、今日/本周/本月支出、隐藏金额切换时有过渡。
- 预算条首次显示时从零增长，金额变化时平滑过渡。待确认支付横幅出现和消失时改为尺寸过渡，不再跳动。
- 快捷操作和快捷交易按下时略微缩小。
- 新记的账单会在“最近交易”中短暂高亮。高亮要等首页重新成为当前页面才开始，所以从语音面板或记账页保存后，关闭页面时还能看到。恢复备份、批量导入等一次新增超过 3 笔时不高亮。

动效只在初次进入、点击或数据变化时运行，结束后不再占用帧；没有循环动画，不新增模糊层，也不引入新依赖。系统开启“移除动画”时全部直接跳到结果。

## 隐私

语音解析请求新增最多 5 笔相似历史账单的标题、类型、分类和账户 ID，不包含金额、备注和日期。账户和分类列表原来就会发送。

## 数据兼容

不涉及存储结构、SQLite `user_version` 或备份 schema 的变化。语音草稿仍保存在原来的扩展字段中；说过修改的草稿，其原文会包含“；补充：”拼接的内容。

## 验证

- 静态检查无问题；Flutter 全量测试 261 项通过（新增 11 项），1 项因缺少本地私人样本跳过。
- Android 原生单元测试 23 项通过（新增音量计算测试）。
- ARM64 release 构建通过：安装包版本为 `0.5.0+9`，应用 ID 为 `com.findash.fin_dash`，签名证书与 0.4.1 一致。

自动化测试覆盖了以下场景：

- 修改后的草稿只改动提到的字段，并保留用户确认过的字段；
- 相似账单不带金额和备注，也不带已归档账户；
- 提示词的内容；
- 小部件的补充沿用原草稿；
- 缺失账户从主按钮打开选择面板；
- 再记一笔；
- 静音提示；
- 首页入场动画不重播；
- 新记账单在面板关闭后才高亮。

真机上的识别准确率、录音期间加载模型的 CPU 占用和等待时间、动效帧率，仍需用目标手机和真实记账录音验收。
