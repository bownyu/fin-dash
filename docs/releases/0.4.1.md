# FinDash 0.4.1

日期：2026 年 10 月 3 日。Android 构建号：8。

0.4.0 没有单独公开发布，本版同时包含 0.4.0 与 0.4.1 的全部更新。从 0.3.0 可直接覆盖升级。

## 0.4.1：AI 对话卡顿修复

AI 回复过程中，输入和输出会出现明显卡顿。原因有三处：

- 每次保存（发送消息、每轮模型回复、每次工具调用、任务进度）都会在主线程对新旧两份完整聊天记录排序、做 JSON 编码并计算 SHA-256，以判断哪些数据域发生了变化。聊天记录包含工具结果和模型上下文，会持续增长；一次回复会触发十余次保存。
- 保存后对话页重建时，每个方案的审阅都会重新扫描全部聊天记录，并复制整个账本，已经结束的方案也不例外。
- 每轮请求和每次工具调用写入调试日志时，都会触发所有订阅运行状态的页面重建。

对应修改：

- 数据域变更检测改用结构比较：共享的字符串和子树先按引用判等，不再编码或哈希。
- 方案审阅在同一账本快照内只扫描一次聊天记录；没有待确认项的方案不再复制账本。
- 调试日志改用独立通知，只有调试记录页订阅；长对话列表改为按键建立索引来定位行。

合成数据（400 条消息、约 5.4 MB 聊天记录、12 个待确认方案），桌面调试模式下测量：

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| SQLite 单次保存的主线程最长阻塞 | 约 350 ms | 约 4 ms |
| SQLite 单次保存总耗时（含后台线程写库） | 约 600 ms | 约 37 ms |
| 写调试日志引起的对话页重建 | 每条日志 1 次 | 0 次 |

## 0.4.0：AI Native 业务内核

- 手动、语音、通知、导入和 AI 准备的交易共用同一套校验规则；账本锁定后，原有的审阅方案不能再提交。编辑表单会检测记录是否已被修改，提交失败时保留输入。
- 聊天工具可以查询应用的实际能力；查询结果带有范围、整数分金额、快照和完整性信息。支持有预算限制的组合分析，不执行任意代码或 SQL。
- 新增“任务与回执”：可补全账户等信息、继续中断的任务、查看方案与保存结果。语音草稿可以恢复；忙碌时最多排队 3 条，并可单独停止。
- 长期记忆、偏好和目标先显示待审阅内容，确认后才保存，并可在满足条件时撤销。
- 查询结果以原生数据卡片展示；查询程序可以保存，之后在“常用分析”中重新计算。
- 元数据写入与账务数据分离，AI 状态、日志和聊天不再导致账单页重建。原生端 SQLite 支持只提交受影响的记录，并支持索引分页查询。

## 数据兼容

- 0.4.0 将备份 schema 升至 2，仍可读取 schema 1 和旧版 wallet 备份。新增分类 ID、来源和日期精度字段；无法确认的历史来源和时间精度标记为 unknown。旧 JSON 源文件、损坏恢复副本和恢复前快照继续保留。
- 0.4.1 不涉及存储结构、SQLite `user_version` 或备份 schema 的变化。
